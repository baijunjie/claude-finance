# 科技公司权力评估（Power Eval · 7 Powers）

评估一家科技公司是否值得长期持有。与 `munger-eval` 的分工：芒格框架要求"10 年后还在做同样的生意 + 10 年 ROIC ≥ 15%"，这两条会把绝大多数科技公司在第一关就误杀——不是因为它们不好，而是因为**科技公司的护城河是动态形成的，利润被 GAAP 系统性扭曲**。本 skill 换掉这两个前提，其余纪律（否决制、证据驱动、逆向优先）完全沿用。

评估的目的不是给热门科技股找买入理由，而是**寻找否决它的理由**：先问"它凭什么能持续赚到超额利润，且竞争者为什么抄不走"，再问"当前股价隐含的假设需要发生什么奇迹"。

## 为什么科技公司要换一套框架

| 芒格框架的前提 | 为什么对科技公司失效 | 本框架的替代 |
|---------------|-------------------|-------------|
| 10 年后还在做同样的生意 | 技术代际每 5–10 年翻一次；要求"生意不变"等于只买夕阳资产 | F1 追问护城河附着在**一代技术**上还是**跨代际资产**（分发、数据、生态、客户流程）上 |
| 10 年 ROIC ≥ 15% 的历史记录 | 增长期公司把获客与研发全部费用化，GAAP 利润为负；ROIC 分母（投入资本）对轻资产公司近乎无意义 | F3 用单位经济与口径校正（SBC、资本化 R&D、RPO）测量**真实**盈利能力与到 FCF 的路径 |
| 静态护城河（已成立才计分） | 科技公司的权力在**起飞期**形成，成立时估值已反映；等到证据齐备往往已过窗口 | F2 七种权力 + 权力形成阶段判断（Power Progression） |
| P/E 20–30 倍是上限 | 高增长 + 高毛利公司当期 P/E 无意义，"便宜"的科技股往往是权力正在流失的 | F6 反向 DCF：不给目标价，只测当前价格隐含假设的可达成难度 |
| 逆向清单以杠杆/周期为主 | 科技公司的毁灭方式是平台改规则、开源追平、通用模型吃掉需求、稀释失控 | F5 科技专属毁灭性风险清单 |

## 评估原则

- **Power = 差异化收益 + 进入壁垒**（Helmer 的定义，两者缺一不成立）。任何一条权力的论证都必须同时回答："它比竞争者多赚在哪（Benefit）"和"竞争者为什么不能照抄（Barrier）"。只有 Benefit 没有 Barrier 的是**产品优势，不是权力**——这是本框架最常触发的否决。
- **结构层否决，增长/估值层降级**：权力（F2）、创始人诚信与资本配置（F4）、颠覆与依赖风险（F5）是结构性问题，不及格即否决；增长质量（F3）与估值（F6）不及格只降级为"观察"——好生意不该因为"现在贵"或"现在还亏"被一票砍掉。唯一例外见 F3 的单位经济硬开关。
- **逆向优先**：先写"这笔投资如何亏掉 50%"，再写"它为什么好"。
- **证据驱动**：禁止用形容词代替证据。"生态强大"不是证据，"付费开发者 X 万、第三方应用贡献 Y% 的用户使用时长、迁出需重写 Z 类集成"才是。
- **区分权力与叙事**：TAM 很大、赛道很热、技术很先进、创始人很强——这四条都不是权力。逐条对照 references/seven-powers.md 的伪权力清单。
- **承认不知道**："看不懂它怎么赚钱"、"无法判断下一代技术的赢家"是合法且体面的结论，比强行给分更有价值。

## 工作流程

### 第 0 步：数据收集与公司类型分档

**数据收集**（来源优先级：用户提供的材料 > 联网搜索最新财报/招股书/投资者材料 > 模型已有知识，并注明数据截止时间）：

- 近 5–10 年（新上市公司用全部可得年份）：营收及其拆解（有机/并购/价/量）、毛利率、经营利润率、GAAP 与调整后口径的差额构成
- 现金流：经营现金流、资本开支（含资本化研发与云基础设施）、自由现金流、股权激励（SBC）绝对额与占营收比
- 股本：稀释后股本历年变化、回购额 vs SBC 额、可转债与认股权证
- 订阅/平台指标（按类型取，见 references/company-archetypes.md）：NRR/GRR、RPO 与 cRPO、客户数与大客户数、DAU/MAU、ARPU、GMV 与 take rate、设计中标（design win）、算力交付量
- 客户与供应商集中度、单一平台/单一大客户收入占比
- 管理层：创始人是否在任、持股比例（含投票权）、薪酬挂钩指标、历史并购回报、资本配置记录
- 当前估值：市值、EV、EV/S、EV/毛利、EV/FCF、当期与远期 P/E、隐含增长
- 竞争格局：主要竞争者的同口径指标（毛利率、增速、份额），以及开源/通用模型的替代进度

数据不足时明确标注"❓ 数据缺口"，不要编造。招股书/投资者材料属于有立场来源，引用时注明。

**类型分档**：读取 [references/company-archetypes.md](references/company-archetypes.md)，判定公司属于哪一类原型（平台生态 / 订阅软件 / 消费互联网 / 交易市场与支付网络 / 半导体与硬件 / AI 模型与算力基础设施）。分档不是过滤器，是**路由**——它决定 F3 用哪张量化门槛表、F6 用哪套估值口径、F5 优先查哪几条风险。

横跨多类型的公司（如既有云平台又有消费硬件）：按**利润来源**而非营收占比定主档，并明确说明另一类业务如何单独处理（分部估值或作为可选项价值）。

### 第 1 步：生意机制与 S 曲线定位（F1）

回答四个问题，任何一个答不出即标记"看不懂"：

1. **它靠什么赚钱**？谁付钱、为什么付、付多少、多卖一单位的增量成本是多少？要求一段外行能听懂的话。
2. **S 曲线定位**：它骑在哪条采用曲线上？该曲线当前渗透率大致在什么位置（萌芽 / 加速 / 成熟 / 衰退）？渗透率的分母（真实可服务市场，不是公司自报 TAM）怎么算出来的？
3. **代际归属（本层核心）**：它的优势附着在**一代技术**上，还是附着在**跨代际资产**上？跨代际资产指：分发渠道与用户默认位、专有数据与反馈回路、开发者与生态、嵌入客户业务流程的位置、品牌心理锚点。只附着在一代技术上的优势，会在下一代清零——这不等于否决，但必须在 F5 与 Pre-mortem 中按"代际风险"重点处理。
4. **关键变量**：决定它未来 5 年盈利的 2–3 个变量是什么？可预测吗？

判定分三档：**通过 / 有条件通过 / 不通过**。"有条件通过"用于机制讲得清但曲线位置或代际归属存疑的情形，必须写明要求用户自问的具体问题。

判定主体是**用户**，不是 Claude。如果生意模式需要专业背景才能判断（前沿模型架构、EDA 工具链、加密协议经济学），提示用户自问是否真正理解。

**F1 不通过时不要就此终止**：最终结论锁定为"放弃（看不懂 / 无法判断代际归属）"，并在结论速览的否决原因中写明 F1 是首要否决项，但其余各层照常完成，作为否决证据链——后续若用户补足认知，备忘录仍可复用。

### 第 2 步：七种权力（F2，结构否决项，核心）

读取 [references/seven-powers.md](references/seven-powers.md)，逐条检验七种权力（规模经济、网络经济、反定位、转换成本、品牌、独占资源、流程优势）：

- 每条判定"有 / 无 / 存疑"，**成立的每一条必须分别写出 Benefit 与 Barrier**，只有 Benefit 的记为"无"
- **权力形成阶段（Power Progression）**：这家公司现在处于"仍能建立新权力的窗口期"，还是"只能维持既有权力"？窗口期已关闭的成熟公司，权力只会随代际变迁折旧
- **权力方向**：变强还是变弱？给出可观测信号（份额、提价、留存、竞争者行为）
- 逐条对照伪权力清单排除误判（技术领先、先发优势、用户量大、数据"很多"、热门赛道、明星创始人、资本雄厚、可 fork 的开源生态）

🚨 否决条件：没有任何一条权力同时具备 Benefit 与 Barrier；或唯一成立的权力正在被证据确认地瓦解。

### 第 3 步：增长质量与单位经济（F3，降级项 + 单位经济硬开关）

读取 [references/unit-economics.md](references/unit-economics.md)，按三块顺序执行：

1. **口径校正**（先把 GAAP 与"调整后"的失真拆掉）：SBC 按真实成本处理、资本化 R&D 与云成本还原、递延收入与 RPO 交叉验证、并购摊销与商誉、FCF 的营运资本与 SBC 成分。得出**校正后真实盈利能力**（真实 FCF ≈ 报表 FCF − SBC，或 − 抵消稀释所需的回购额）。
2. **增长质量拆解**：有机 vs 并购 vs 提价 vs 汇率；量 vs 价；净新增 ARR/客户数趋势（看净新增的趋势，不看累计值）；增长是否靠补贴、免费额度或渠道压货买来的。
3. **按类型对照量化门槛表**（原型对应的门槛见 references/unit-economics.md §3）。

🚨 **单位经济硬开关（本层唯一的否决触发器）**：以下三条任一不成立即 F3 否决，不走降级：
- ① 边际贡献为正（毛利 − 增量获客与服务成本 > 0，且随规模改善）
- ② 获客成本回本期可测算，且显著短于客户生命周期
- ③ 达到 FCF 转正不需要不可得的规模（隐含所需营收未超过合理可服务市场，或不需要持续巨额外部融资）

⚠️ 降级（非否决）：门槛表多项不达标、增长质量差（主要靠并购或提价）、口径校正后真实盈利能力显著弱于报表 → 结论降为"观察"。

### 第 4 步：创始人与资本配置（F4，结构否决项）

- **诚信**：披露是否坦承坏消息？关键指标是否曾被改口径或停止披露？关联交易与循环交易（客户同时是投资方、供应商入股客户）？监管处罚与诉讼？
- **资本配置**：历史并购回报（收购价 vs 后续贡献，注意用股权支付的真实成本）；回购是在低估时还是在高位对冲稀释；研发投入产出（新产品线是否形成第二增长曲线，还是持续烧钱无果）
- **稀释纪律**：SBC 占营收比与同类对比；稀释后股本长期趋势；回购是否只够抵消 SBC（那不是回报股东，是替员工付账）
- **激励**：创始人持股与投票权结构；薪酬挂钩什么（警惕只挂钩营收增速、GMV、调整后 EBITDA 或股价短期表现）；双层股权下小股东的救济手段
- **长期主义证据**：是否有为长期牺牲短期的实际决策记录（而不只是股东信里的宣言）

🚨 否决条件：诚信硬伤（欺诈红旗命中 ≥ 2 条，见 references/disruption-risks.md §3，此时 F4 评分上限 3）；或资本配置持续毁灭价值（高位大额并购减值 + 高位回购 + 失控稀释同时出现）。

### 第 5 步：颠覆与依赖风险（F5，结构否决项）

读取 [references/disruption-risks.md](references/disruption-risks.md)，逐条核对毁灭性风险清单（技术代际颠覆、通用模型吃掉需求、开源商品化、平台寄生、单一依赖、监管与法律、治理陷阱、资金链断裂、稀释失控），标注"存在 / 不存在 / 存疑"，并标明**可逆性**。

- 🚨 否决：任一条明确**存在**且不可逆
- ⚠️ 存疑：风险在途但未定 → 至多"观察"，并必须进入 Pre-mortem 的头部路径
- 同时核对 §3 的科技版红旗（叙事与会计），命中的逐条列出

### 第 6 步：估值与隐含预期（F6，降级项）

读取 [references/reverse-dcf.md](references/reverse-dcf.md)，做**反向 DCF**而不是正向估值：

- 不问"它值多少钱"，问"**当前 EV 隐含了什么假设**"：倒推支撑当前价格所需的 10 年营收 CAGR、终局 FCF 利润率、退出倍数
- **可验证性检验**：隐含营收对应的市场份额是否荒谬（超过行业总规模是最常见的证伪）？隐含利润率是否高于行业内最好的公司？
- **稀释校正**：股本年增 x% 会吃掉多少年化回报，必须扣掉
- 三档情景（悲观 / 中性 / 乐观）的 10 年年化回报，与机会成本比较。**悲观情形必须包含倍数收缩**——科技股回撤主要来自估值倍数而非业绩
- 可选项价值（新业务、新市场）允许估算，但必须**单列**，不计入基础情形
- 不做精确 DCF。如用户需要完整三表模型或正向 DCF，建议另行调用 `financial-analysis:dcf` skill

⚠️ 降级（非否决）：隐含假设需要"一切顺利"或"奇迹"才能成立 → 结论降为"观察，等价格"。

### 第 7 步：Pre-mortem 与反方压力测试

读取 [references/disruption-risks.md](references/disruption-risks.md) §1 与 §4，执行：

1. **Pre-mortem**：假设 10 年后这笔投资亏损 50%，写出 3–5 条最可能的原因及当前可见的早期信号。每条必须给出**估算概率区间**（10 年内发生的主观概率，如 20%–30%），并满足：① 概率与排序一致（排第一的最高）；② 用宽区间表达不确定性，禁止伪精确的单点数字；③ 与第 6 步悲观情景的概率口径互相校验，不应明显矛盾。
2. **最强空头论点（steel-man）**：写出你能构造的最有说服力的空头论点——不是弱化版，而是假设对方比你聪明且读过同样的材料。然后逐条回应；回应不了的，如实写"无法反驳"，并据此下调评分。
3. **基础比率校验**：历史上同类公司（同原型、同增速、同估值倍数）此后 10 年的平均回报是多少？本案凭什么是例外？
4. **心理误判自查**：核对本次分析自身是否中了 §4 清单中的偏误（叙事偏误、TAM 幻觉、增长外推、技术崇拜、社会认同、FOMO 等）。中招的回到对应步骤修正评分，并记录修正过程。

### 第 8 步：输出评分卡 + 投资备忘录

按 [assets/memo-template.md](assets/memo-template.md) 模板生成备忘录，保存到当前工作目录 `output/power-eval/<公司名>-<日期>.md`（目录不存在时先创建）。

## 判定标识（全文统一使用）

| Emoji | 含义 | 用在哪里 |
|-------|------|---------|
| ✅ | 确认通过 / 确认存在（证据充分的正面判定） | F1 通过、权力"有"、风险"不存在"、红旗未命中、门槛达标 |
| 🚨 | 确认风险 / 否决项（证据充分的负面判定） | 毁灭性风险"存在"、红旗命中、触发否决/降级的分项 |
| ⚠️ | 存疑（证据不足或方向不明，结论可被新证据翻转） | 权力"存疑"、风险"存疑"、有条件通过、降级项 |
| ❓ | 数据缺口（数据不全、待核实，影响判定可靠性） | 正文中凡引用估算值/未核实数据处、数据缺口列表 |
| ❌ | 不通过 / 无（明确的"没有"） | F1 不通过、权力"无"、门槛不达标 |

使用规则：结论速览表、七种权力表格、毁灭性风险清单表格、量化门槛对照表的判定列**必须**带标识；正文段落中的关键判定（Barrier 是否成立、单位经济硬开关、隐含假设可达成性、欺诈红旗）在判定词后紧跟标识；不要在叙述性文字中滥用，每个标识只标判定本身。

## 评分与结论规则

| 过滤器 | 评分 | 及格线 | 性质 |
|--------|------|--------|------|
| F1 生意机制与曲线定位 | 通过 / 有条件通过 / 不通过 | 不通过 → 结论锁定"放弃（看不懂）"（其余各层仍完成，见第 1 步） | 否决 |
| F2 七种权力 | 0–10 | < 6 → **否决** | 结构否决 |
| F3 增长质量与单位经济 | 0–10 | 单位经济硬开关任一不成立 → **否决**；否则 < 5 → **降级为"观察"** | 降级 + 硬开关 |
| F4 创始人与资本配置 | 0–10 | < 5 → **否决** | 结构否决 |
| F5 颠覆与依赖风险 | 通过 / 存疑 / 否决 | 明确存在且不可逆 → **否决**；存疑 → 至多"观察" | 结构否决 |
| F6 估值与隐含预期 | 0–10 | < 5 → **降级为"观察"** | 降级 |

**结论三档：**

- **出手**：F1 通过 + F2 ≥ 8 + F3 ≥ 6 + F4 ≥ 6 + F5 通过 + F6 ≥ 5
- **观察**：否决项全过但未达出手线（F2 = 6–7、F3 或 F6 被降级、F5 存疑、或关键数据缺口影响判定）
- **放弃**：任一否决项不及格，必须写明**单一首要否决原因**

注意用词区分：F2/F4/F5 与 F3 硬开关不及格是"**否决**"；F3/F6 评分不及格是"**降级**"。结论速览表统一填入"否决/降级原因"一行。

- 评分必须附证据引用；没有证据支撑的分项最高给 5 分
- F2/F3/F4/F6 每层末尾必须附"**评分依据**"，对照 references 中的评分锚点说明为何给该分、为何没给更高/更低
