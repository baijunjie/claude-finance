# power-eval 设计记忆

记录 `power-eval`（科技公司权力评估）skill 的非显而易见设计决策。skill 结构本身见 `.claude/skills/power-eval/`，此处只记"为什么这么设计"。

## 1. 为什么不复用 munger-eval，而另开一个 skill

munger-eval 有两个前提会把绝大多数科技公司在前两关误杀，且这两条**不能靠放宽阈值修补**，因为失效的是口径本身：

- **"10 年后还在做同样的生意"**：技术代际每 5–10 年翻一次，这条等于只买夕阳资产。替代口径是 F1 的**代际归属**——追问优势附着在一代技术上，还是附着在跨代际资产（分发位、专有数据与反馈回路、开发者生态、嵌入客户流程、品牌锚点）上。
- **"10 年 ROIC ≥ 15% 的历史记录"**：增长期科技公司把获客与研发全部费用化，GAAP 利润为负；ROIC 的分母对轻资产公司近乎无意义。替代口径是 F3 的**单位经济 + 口径校正**。

其余纪律（否决制、证据驱动、逆向优先、emoji 判定标识、references/ 明细 + assets/ 模板 + 输出到 `output/<skill>/`）全部沿用，两个 skill 的备忘录可对照阅读。SKILL.md 开头保留了一张"芒格前提 → 为什么失效 → 本框架替代"的对照表，是这个 skill 存在理由的浓缩，改动框架时先更新它。

## 2. 骨架选 Helmer 七种权力，而不是自建或 Christensen

- 七种权力有**成熟且可对照的评分锚点**，且 Power = Benefit + Barrier 的定义天然构成一条硬检验：只有 Benefit 没有 Barrier 的记"无"。这是本框架最常触发的否决，也是它区别于"讲故事式护城河分析"的关键。
- 反定位（Counter-Positioning）是七种权力里最难被替代的一条：它解释了"在位者明知威胁却**不能**跟进"这种科技行业特有的结构，其他框架里没有对应概念。同时它有**保鲜期**，必须评估剩余年限，否则会把一次性的模式创新当成永久护城河。
- Christensen 颠覆理论对已经赢下市场的成熟科技巨头解释力弱，只作为 F5 的一条风险（技术代际颠覆），不做主轴。

## 3. 判定机制：结构层否决 + 增长/估值层降级

munger-eval 是四层全硬否决。这里改成分层，理由是**科技公司的"现在亏"和"现在贵"是时点问题，不是结构问题**：

- 硬否决：F2 权力、F4 创始人诚信与资本配置、F5 颠覆与依赖风险。这三层不及格意味着生意本身或治理有结构性缺陷。
- 只降级为"观察"：F3 增长质量、F6 估值。避免把好生意因为估值高或尚未盈利一票砍掉。
- **例外：F3 的单位经济硬开关**（边际贡献为正 / CAC 可回本 / FCF 转正不需要不可得的规模）。这三条问的是"生意本身成不成立"，与"现在是否赚钱"无关，任一不成立即否决，不走降级。这是为了防止降级机制被滥用成"所有亏损公司都进观察层"。

阈值取法：F2 < 6 否决（比 munger 的 F2 < 7 低一档，因为权力常在起飞期尚未在财务上体现）；出手仍要求 F2 ≥ 8。

## 4. 类型分档是路由，不是过滤器

第 0 步的六类原型（平台生态 / 订阅软件 / 消费互联网 / 交易市场 / 半导体硬件 / AI 基础设施）不打分、不否决，只决定 F3 用哪张量化门槛表、F6 用哪套估值口径、F5 优先查哪几条风险。

- 按**利润来源**而非营收占比定主档——营收占比会把高营收低利润的业务误判成主业。
- 半导体/硬件同时有科技属性与周期属性，因此在 F3 强制标注周期位置、在 F6 强制用周期中值盈利（禁用峰值）。这是唯一一处按原型施加的硬性约束。

## 5. F6 只做反向 DCF，不给目标价

科技公司正向估值几乎总是"输入假设决定输出结论"，换一个终局利润率目标价能翻倍。所以 F6 的输出不是估值，而是**隐含假设三元组**（隐含营收 CAGR / 隐含终局真实 FCF 利润率 / 隐含退出倍数）+ 三道证伪：

1. **份额检验**——隐含营收对应的市场份额是否荒谬（最常触发；隐含营收超过行业总规模是常见的直接证伪）
2. **利润率检验**——隐含利润率是否高于同原型最好的公司
3. **竞争一致性检验**——同赛道各家的隐含营收加总是否已超过市场容量（市场经常给每家都定价成赢家）

评分锚点因此是"隐含假设的可达成难度"，不是"贵不贵"。另有两条纪律容易在维护时被削掉，不要删：**悲观情景必须包含倍数收缩**（科技股回撤主要来自倍数而非业绩）、**稀释校正必须显式扣进年化回报**（SBC 对股东回报的侵蚀是系统性的）。

## 6. 第 7 步为什么不用"多元思维模型交叉验证"

munger-eval 用四个学科模型做交叉验证。科技股的主要误判来源不是缺少学科视角，而是**叙事驱动**，所以换成三件更对症的事：

- **最强空头论点（steel-man）**：要求假设对方比自己聪明且读过同样材料，逐条回应；回应不了的如实写"无法反驳"并下调评分。这比泛化的模型清单更能压住确认偏误。
- **基础比率校验**：同原型、同增速、同倍数的公司此后 10 年的实际回报——治"这次不一样"。
- **心理误判自查**：清单按科技股重写，头部是叙事偏误、TAM 幻觉、增长外推、技术崇拜、FOMO。

## 7. AI 时代的专项风险是有意写进框架的，不是时事补丁

F5 的毁灭性风险清单里有四条是这一代科技公司的主要死法，且都不在传统护城河分析的视野内：**通用模型吃掉需求**、**开源商品化**、**平台寄生**、**循环交易**（客户同时是投资方、供应商入股客户后客户用融资款采购）。

其中"通用模型吃掉需求"配了一条反向判据，避免一刀切地看空所有软件：如果产品的价值在于**系统记录与工作流治权**，通用模型是它的功能增强而非替代；如果产品价值只是"把非结构化工作变成结构化流程"，则订阅逻辑会被跳过。

## 8. 与其他 skill 的分工（维护时保持三处同步）

- `munger-eval` — 传统价值股（消费、工业、金融）；其"注意事项"里有指向 power-eval 的路由。
- `chokepoint-screen` — 产业链层面筛候选池；其"注意事项"里的单标的深评路由已同时指向 munger-eval 与 power-eval。
- `power-eval` — 单一科技标的深评；"注意事项"里指回上述两者与 trade/call/short-eval。

改动任一 skill 的适用边界时，这三处路由说明与 README 的 skill 列表要一起改。
